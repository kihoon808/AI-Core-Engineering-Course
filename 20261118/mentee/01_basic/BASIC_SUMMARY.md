# basic 실습 요약 및 학습 정리 노트

Embedding과 pgvector를 활용해 시맨틱 검색(Semantic Search) 및 RAG용 Retriever 파이프라인을 구축하는 8단계 핵심 패턴 정리입니다.

---

## 1. 실습별 핵심 요약

| 실습 | 주제 | 핵심 내용 |
|---|---|---|
| **01** | 검색 대상과 ID (`01_knowledge`) | 원문 ID 고정 및 불변성 유지, E5 문서 입력 비대칭 포맷(`passage: 제목 본문`) 생성, 벡터 생성 전 원문 메타데이터 매핑 |
| **02** | 벡터·유사도·거리 (`02_similarity`) | 내적(Dot), 코사인 유사도(Cosine), 유클리드 거리(L2) 연산 구현, 영벡터 방어 로직 및 거리 지표별 수학적 특성 이해 |
| **03** | E5 문장 임베딩 (`03_e5_embeddings`) | `intfloat/multilingual-e5-small` 모델 로드, `query:` / `passage:` 비대칭 접두어 적용 및 384차원 단위 벡터 정규화 |
| **04** | 서버 확장과 Python 연결 (`04_pgvector_setup`) | PostgreSQL 18에 pgvector 0.8.7 확장 활성화(`CREATE EXTENSION vector`), 코사인 거리 연산자(`<=>`), psycopg 기반 연결 검증 |
| **05** | 원문·벡터 저장과 Top-k (`05_topk_storage`) | `day23_search_docs` 테이블(`vector(384)`) 생성, 9건 지식 임베딩 적재(upsert), 모델 필터링 및 코사인 거리 기준 Exact Top-k 검색 |
| **06** | Exact·HNSW·EXPLAIN (`06_hnsw`) | `vector_cosine_ops` 기반 HNSW 인덱스 정의, `EXPLAIN (ANALYZE, BUFFERS)` 실행 계획 분석, 소규모 데이터에서 Seq Scan 선택 원리 이해 |
| **07** | 검색 결과 정성평가 (`07_relevance`) | 테스트 케이스북 구성, 교육용 골드 라벨(`관련`, `부분 관련`, `무관`) 판정, 거리 수치와 실제 사실적 관련도의 괴리 및 사람 검토 필요성 확인 |
| **08** | AI Agent용 Retriever (`08_retriever_project`) | 질문 검증부터 E5 쿼리 인코딩, pgvector Top-k 검색, RAG Context 후보 포맷팅까지 연결된 Retriever 파이프라인 완성 |

## 2. 기억해야 할 5가지 핵심 원칙

1. **E5 비대칭 임베딩 규격을 엄격히 준수한다**
   - E5 모델은 질의(`query: `)와 문서(`passage: `) 접두어를 엄격히 구분합니다. 접두어가 누락되거나 뒤바뀌면 동일한 의미라도 고차원 공간상 거리가 왜곡됩니다.
   - 코사인 거리 계산의 일관성을 위해 인코딩 시 반드시 단위 벡터 정규화(`normalize_embeddings=True`)를 수행해야 합니다.

2. **벡터 거리와 실제 의미적 관련성은 동일하지 않다**
   - 코사인 거리(`<=>`)는 단지 고차원 임베딩 공간의 기하학적 각도일 뿐이며, 정답 확률이나 사실 일치도가 아닙니다.
   - 키워드가 유사해도 질문의 실제 요구사항(예: 기간 명시 유무)에 부합하지 않을 수 있으므로, 사람의 근거 대조나 상위 정성 평가 단계가 필수적입니다.

3. **소규모 데이터셋에서의 Seq Scan은 정상 동작이다**
   - 인덱스(HNSW)가 생성되어 있더라도 데이터가 소량일 때는 옵티마이저가 전체 순차 탐색(Seq Scan)이 인덱스 탐색 오버헤드보다 빠르다고 판단합니다.
   - HNSW는 대규모 데이터셋에서 검색 속도를 확보하기 위한 근사 검색(ANN)이며, 9건 규모에서는 Exact 탐색이 더 정확하고 빠릅니다.

4. **벡터 DB에서도 원문 메타데이터와 모델 식별자를 함께 격리·추적한다**
   - 벡터 값만 저장하면 어떤 텍스트에서 나온 것인지 역추적이 불가능하므로 원문과 버전을 반드시 함께 저장해야 합니다.
   - 서로 다른 임베딩 모델의 벡터는 차원이 같더라도 공간 좌표계가 완전히 다르므로, `embedding_model` 컬럼을 필터링하여 이종 모델 간 혼합 조회를 방지해야 합니다.

5. **모의 실행(fixture)과 실제 실측(live)을 엄격히 구분한다**
   - fixture는 함수 인터페이스와 데이터 흐름을 점검하기 위한 단위 테스트일 뿐, 실제 모델 품질이나 DB 연동을 증명하지 않습니다.
   - 운영 환경 배포 전에는 반드시 실제 환경(PostgreSQL + pgvector + SentenceTransformer)에서의 live 실측 결과를 검증해야 합니다.
