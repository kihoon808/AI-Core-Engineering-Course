## 2. 오늘 학습한 주요 개념

### 2.1 검색 실패 vs 생성 실패 vs 시스템 장애 분리
- RAG 파이프라인의 실패 원인을 정확히 찾으려면 `System -> Candidate -> Context -> Generation` 순서로 점검해야 합니다.
- **시스템 장애(`system_error`)**: API 인증 오류, GPU OOM 등 인프라/코드 실행 실패로 검색·생성 품질 지표와 분리해야 합니다.
- **검색 후보 누락(`retrieval_candidate_miss`)**: 1차 Retriever가 정답 문서를 Top-K 후보에 아예 가져오지 못한 상태입니다.
- **Context 누락(`retrieval_context_miss`)**: 후보에는 있었으나 Reranking 또는 Context 길이 제한(Top-N)으로 최종 프롬프트에서 제외된 상태입니다.
- **생성 근거 미기반(`generation_ungrounded`)**: Context에 정답 근거가 존재함에도 LLM이 근거 없는 내용(환각)을 생성한 상태입니다.

### 2.2 Gold Dataset과 데이터 누출(Data Leakage) 방지
- **Gold Label**: 사람이 정의한 정답 문서/청크 ID 집합입니다.
- **누출 방지**: 평가 대상(Target)을 실행할 때는 `question_id`, `question`, `category`, `history`만 전달해야 하며, `gold_chunk_ids`나 `reference_answer`를 Target 입력에 절대 포함해서는 안 됩니다.
- **무정답(No-answer) 질문 분리**: Gold가 비어 있는 질문(`[]`)을 Recall이나 MRR 평균 계산 시 `0.0`으로 합산하면 전체 성능 지표가 왜곡됩니다. 따라서 `None`(`null`)으로 반환해 평균 집계에서 제외하고 별도 건수(`no_answer_count`)로 관리합니다.

### 2.3 Retrieval 및 Ranking 평가 지표
- **Recall@k**: Top-k 검색 결과에 포함된 고유 Gold 문서 수 / 전체 고유 Gold 문서 수. 정답 문서를 얼마나 빠짐없이 찾았는지 측정합니다. (중복 ID 제거 필수)
- **RR(Reciprocal Rank) & MRR(Mean Reciprocal Rank)**: 첫 번째 정답 문서가 등장한 순위의 역수(`1 / rank`)와 그 평균입니다. Recall이 같더라도 정답이 상단에 배치될수록 높은 점수를 받습니다.

### 2.4 생성 품질: Faithfulness (충실도)
- **Faithfulness**: 생성된 답변을 개별 주장(Claim)으로 분해했을 때, 검색된 Context가 실제로 지지하는 Claim의 비율입니다.
- **주의점**: Faithfulness는 정답지(Reference Answer)와의 비교가 아니라 **주어진 Context에 근거하는지**를 검증하는 지표입니다. 또한 모델이 반환한 Citation ID가 존재한다는 사실만으로 Faithfulness가 자동 보장되지는 않습니다.

### 2.5 A/B 비교 및 Agent Tool 연결 전 검증
- **공정한 비교**: Before/After 점수 차이(`score_delta`)를 비교할 때는 동일한 데이터셋 버전(`dataset_version`)과 실행 모드(`offline_fixture` vs `live`)에서만 비교해야 합니다.
- **Trace 누락 처리**: `ranked_ids`, `included_ids` 같은 필수 Trace 필드가 누락되었을 때 빈 리스트로 덮어쓰면 시스템 오류가 0점 성능으로 오인되므로 명시적 예외로 보고해야 합니다.
- **Agent 연결 전 체크리스트**: Day29 Agent Tool로 연결하기 전에는 출처(Citation) 검증, 문서 접근 권한(RBAC), 시스템 오류 및 No-answer에 대한 안전한 Fallback 정책을 반드시 확인해야 합니다.
