# 두 테이블 관계 워크시트

categories                           knowledge
┌──────────────────────┐             ┌──────────────────────┐
│ id                   │             │ id                   │
│ name                 │             │ title                │
└──────────────────────┘             │ content              │
                                     │ category_id          │
                                     └──────────────────────┘

1. 각 표의 PK: categories.id / knowledge.id
2. FK의 출발 열 → 대상 열: knowledge.category_id → categories.id
3. 분류 한 개에는 지식이 몇 개까지 연결될 수 있는가? 0개 이상 (0..N, 1:N 관계)
4. 지식 한 개는 분류 몇 개를 참조하는가? NOT NULL FK 제약조건이므로 정확히 1개
5. 지식이 있는 분류를 삭제하면? ON DELETE RESTRICT 제약조건에 의해 부모 행 삭제 거부 (참조 무결성 위반 방어)
6. 제목 중복은 허용되는가? 허용 (knowledge.title 열에 UNIQUE 제약조건이 설정되어 있지 않음)
7. IDENTITY와 PK의 역할은 어떻게 다른가? IDENTITY는 고유 정수 번호를 자동 시퀀스로 발급하는 메커니즘이며, PK(Primary Key)는 튜플의 유일성(Unique)과 결측 금지(Not Null)를 강제하는 논리적/물리적 제약조건임

그림과 실제 제약조건은 별개입니다. 공통 준비 SQL과 실제 pg_constraint 결과를 대조합니다.
