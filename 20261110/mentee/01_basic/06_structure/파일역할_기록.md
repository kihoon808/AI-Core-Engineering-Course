- 요청 등록 위치: main.py의 `@app.post("/api/knowledge", status_code=201, response_model=Knowledge)`
- 내가 설명하는 의미: HTTP POST 메서드와 /api/knowledge 경로를 create_knowledge 핸들러 함수에 매핑하며, 201 상태코드와 Pydantic 응답 모델을 바인딩합니다.

<!-- TODO B06-R2: main.py의 저장 호출과 storage.py의 실제 파일 쓰기 함수 위치를 찾으세요. -->
- 저장을 호출하는 위치: main.py의 create_knowledge/update_knowledge/delete_knowledge 내부 `write_data(data)` 호출 줄
- 파일에 쓰는 함수: storage.py의 `def write_data(data: dict) -> None`
- 입력·반환·변경되는 것: dict 타입의 data를 입력받아 파일(data/knowledge.json)을 원자적으로 덮어쓰며, 반환값은 None입니다.

<!-- TODO B06-R3: 다음 세 항목의 역할이 다른 이유를 한 문장씩 적으세요. -->
- KnowledgeWrite: 클라이언트가 전송한 HTTP 요청 Body의 필드 및 유효성(Validation)을 정의하는 Pydantic 스키마입니다.
- read_data / write_data: 실제 파일 시스템 I/O를 수행하여 영속 데이터를 읽고 쓰는 스토리지 레이어 함수입니다.
- data/knowledge.json: 서버 재시작 후에도 데이터와 ID 시퀀스를 보존하는 물리적 파일 저장소입니다.
