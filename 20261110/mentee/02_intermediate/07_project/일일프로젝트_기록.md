## 5. 설명과 한계
<!-- TODO P-05: 한 요청이 입력 검증·저장·응답으로 이어지는 위치를 자신의 말로 설명하세요. -->
내가 고른 요청의 흐름: 클라이언트가 POST /api/knowledge로 JSON 페이로드를 전달하면, FastAPI가 KnowledgeWrite Pydantic 모델을 통해 본문 형식을 우선 검증합니다(미달 시 422 반환). 검증 성공 시 LOCK 블록 내에서 read_data()로 기존 상태를 읽고, 현재 next_id를 엔트리 ID로 할당한 후 entries에 append하고 next_id를 1 증가시켜 write_data()로 원자적 파일 저장을 완료합니다. 마지막으로 201 Created와 함께 생성된 엔티티를 반환합니다.
형식 검증과 지식 내용의 사실성 확인이 다른 이유: Pydantic의 형식 검증은 필드의 존재 여부, 데이터 타입, 문자열 최소/최대 길이 등 구조적 문법(Syntax)을 검사할 뿐이며, 해당 지식의 사실 관계나 기술적 정합성(Semantics)은 판별할 수 없기 때문에 별도의 도메인 검증 레이어가 필요합니다.
RAG·Agent 플랫폼에서 이 API의 역할: AI 에이전트와 검색 증강 생성(RAG) 파이프라인에서 참조할 도메인 원본 문서를 수집, 정제, 수정, 삭제하는 단일 진실 공급원(Single Source of Truth, SSOT) 저장소 역할을 담당합니다.
현재의 한계 (로컬·인증/권한·검색/생성): 로컬 파일(JSON) 기반이므로 분산 스케일아웃 시 락 충돌 한계가 있으며, JWT/OAuth2 같은 사용자 인증 및 접근 제어가 없고, 벡터 임베딩 기반의 유사도 검색 엔진이 결여되어 있습니다.

응용 선택: category가 일치하는 결과 / 없는 category의 200+[]: GET /api/knowledge?category=setup 호출 시 2건 반환, 존재하지 않는 category=unknown 호출 시 200 OK와 함께 빈 리스트 [] 정상 반환 확인.
